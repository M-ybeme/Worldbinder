# Environment variable reference

`.env.example` is the source of truth for local defaults and has good inline comments per variable — this document organizes every variable by category with its required/default status, for a single place to check before a deploy. Validated by `packages/config/src/env.ts`'s `apiEnvSchema`/`workerEnvSchema` (Zod) — an invalid or missing required value fails fast at boot, not silently at first use. There's a single root `.env`, not per-app ones; `apps/api`/`apps/worker` scripts wrap themselves in `dotenv -e ../../.env --` to load it.

**Known footguns** (see `CLAUDE.md`): `z.coerce.boolean()` treats the string `"false"` as truthy — this is why boolean env vars use the shared `booleanString()` helper instead. `SMTP_HOST` must stay `127.0.0.1`, not `localhost`, on machines where `localhost` resolves to `::1` first.

## `apps/worker` (validated by `workerEnvSchema`)

Shares `DATABASE_URL`, `REDIS_URL`, `NODE_ENV`, `LOG_LEVEL`, and all `STORAGE_*` variables with `apps/api` above (same values, since both processes talk to the same database/queue/storage) — the worker has no auth, mail, or CORS variables of its own since it never serves HTTP requests to end users.

## `apps/web` (read at build time by Vite, must be prefixed `VITE_`)

| Variable          | Required | Default                 | Notes                                                             |
| ----------------- | -------- | ----------------------- | ----------------------------------------------------------------- |
| `VITE_API_URL`    | No       | `http://localhost:3000` | The real deployed API origin in production                        |
| `VITE_SENTRY_DSN` | No       | unset                   | Same "unset = fully inert" behavior as the backend's `SENTRY_DSN` |

## Production-specific values not yet in `.env.example`

Per Milestone 16's not-yet-executed provisioning checklist (`WORLDBINDER_V1_ROADMAP.md`): `COOKIE_DOMAIN=worldbinder.net`, `CORS_ORIGIN=https://worldbinder.net`, `FRONTEND_URL=https://worldbinder.net`, `VITE_API_URL=https://api.worldbinder.net` (only if the actual Railway topology uses a separate API hostname), real `SMTP_USER`/`SMTP_PASSWORD` from the Resend account, real `STORAGE_*` credentials from the R2 bucket, and real `SENTRY_DSN`/`VITE_SENTRY_DSN` values once a Sentry project exists. None of these have real values yet — this section names what will need to be set, not placeholder values to copy.
